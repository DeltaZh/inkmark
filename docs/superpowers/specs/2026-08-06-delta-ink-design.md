# Inkmark 设计规格

**日期：** 2026-08-06  
**状态：** 待用户审阅  
**平台：** macOS（第一版）  
**仓库目标：** 公开/私有均可，按 GitHub 开源项目标准组织

## 1. 目标

构建一款 Mac 上的 Markdown 编辑器 **Inkmark**，核心体验对齐 参考编辑器：

- **所见即所得（WYSIWYG）**编辑，而非左右分栏预览
- **高兼容**加载现有 参考编辑器 主题 CSS（尽量直接使用，必要时用适配层/补丁）
- 同时扫描 **参考编辑器 主题目录** 与 **本应用自有主题目录**

第一版交付「核心编辑器 + 写作增强」，不做完整 参考编辑器 的全部能力。

## 2. 非目标（第一版明确不做）

- 文件树 / 文档库
- 导出 HTML / PDF
- 表格可视化编辑、数学公式、Mermaid / 图表
- 云同步、插件市场
- Windows / Linux 打包（架构可预留，第一版只保证 macOS）

上述能力规划为后续阶段，不阻塞第一版发布。

## 3. 用户决策摘要

| 项 | 选择 |
|----|------|
| 编辑形态 | 参考编辑器 式所见即所得 |
| 第一版范围 | 核心编辑 + 写作增强（大纲、图片、代码高亮、查找替换、多标签） |
| 技术栈 | Tauri 2 + Web 编辑器 |
| 主题兼容 | 高兼容（直接加载 参考编辑器 CSS + DOM 适配） |
| 主题来源 | 参考编辑器 目录 + 应用自有目录（可开关） |

| 发布 | 落地按 GitHub 标准，最终上传 GitHub |

## 4. 架构

```
┌─────────────────────────────────────────┐
│  Tauri Shell (macOS)                    │
│  · 窗口 / 原生菜单 / 文件对话框          │
│  · 主题目录扫描、.md 读写                │
│  · 应用设置持久化（JSON）                │
└─────────────────┬───────────────────────┘
                  │ IPC
┌─────────────────▼───────────────────────┐
│  React + TypeScript UI                  │
│  · 多标签、大纲侧栏、查找替换、主题选择   │
│  ┌───────────────────────────────────┐  │
│  │ TipTap + 参考编辑器 DOM 适配层         │  │
│  │ · WYSIWYG、Markdown 序列化         │  │
│  │ · 挂载主题 CSS（#write 等结构）    │  │
│  └───────────────────────────────────┘  │
└─────────────────────────────────────────┘
```

### 4.1 职责划分

- **Rust（Tauri）**：文件系统访问、主题扫描、路径安全校验、设置读写；不承载编辑逻辑。
- **前端（React + TS）**：全部 UI 与编辑器状态；以「标签」为文档单位。
- **单一数据源**：每个标签对应一份逻辑上的 Markdown；TipTap 文档为工作副本，保存时序列化为 `.md`。

### 4.2 为何选 TipTap 而非 Milkdown / CodeMirror

- TipTap/ProseMirror 适合真正的 WYSIWYG，扩展大纲、图片、多文档状态成熟。
- 可通过自定义 Node 视图与 HTML 结构，逼近 参考编辑器 DOM，便于主题 CSS 命中。
- CodeMirror 装饰型方案无法很好复用 参考编辑器 预览向主题；Milkdown 的默认 DOM 与 参考编辑器 差距更大，高兼容成本不低于 TipTap 适配层。

## 5. 编辑器与主题

### 5.1 编辑能力（第一版）

支持：标题、段落、列表（有序/无序/任务）、引用、代码块与行内代码、链接、图片、粗体/斜体/删除线、分割线。

快捷键对齐常见 Mac 写作习惯，至少包括：

- `⌘B` / `⌘I` 粗体/斜体
- `⌘⌥1`–`⌘⌥6` 标题级别
- 列表缩进/outdent（如 `⌘[` / `⌘]` 或 Tab / Shift-Tab）
- `⌘S` 保存、`⌘W` 关标签、`⌘F` 查找

交互目标：输入即渲染；用户始终在单一编辑表面操作结构化内容（接近 参考编辑器）。第一版验收硬条件是 **真 WYSIWYG、禁止左右分栏作为主编辑模式**；「点击块后露出原始 Markdown 标记」属于增强体验，可在实现计划中排期，但不作为第一版阻断项。

### 5.2 参考编辑器 DOM 适配层

- 编辑区根节点使用 `#write` 及主题常见依赖的外层结构/class。
- 标题、段落、代码块、图片等映射与 参考编辑器 接近的标签与 class。
- 主题以 stylesheet 链接或注入加载；切换时卸载旧主题并加载新主题。
- 维护「已知不兼容补丁」：对少数依赖 参考编辑器 私有结构的主题做运行时 CSS/DOM 修正，**不修改用户主题源文件**。

### 5.3 主题发现

1. 参考编辑器：`~/Library/Application Support/abnerworks.参考编辑器/themes`
2. 应用自有：`~/Library/Application Support/Inkmark/themes`（名称以实际 bundle id / app 名为准，文档与代码保持一致）
3. 设置项：`read参考编辑器Themes: boolean`（默认 `true`）
4. 支持将 `.css` 导入到自有目录
5. 列表去重：同名时 **自有目录优先**，UI 标注来源（参考编辑器 / 本地）

### 5.4 Markdown 往返

- 打开：文件字节 → UTF-8 文本 → 解析 → TipTap 文档
- 保存：TipTap → 稳定、可读的 CommonMark/GFM 子集 Markdown
- 第一版以 **正确性与可再打开** 优先；完美保留原文件空行/列表标记风格可作为后续增强，不作为第一版验收硬条件

### 5.5 图片

- 支持拖拽与粘贴插入
- 默认将图片复制到文档旁 `assets/`，正文使用相对路径
- 设置中可配置图片保存策略（至少保留「旁路 assets」一种默认策略）

## 6. UI 与功能边界

### 6.1 窗口结构

- 顶栏：多标签
- 左侧可折叠：大纲（标题层级，点击跳转）
- 中央：WYSIWYG 编辑区（主题作用域）
- 底栏：字数或等价统计、文件路径、当前主题名、未保存脏标记
- 原生菜单：文件、编辑、视图、主题、窗口

### 6.2 功能清单

| 能力 | 第一版要求 |
|------|------------|
| 文件 | 新建 / 打开 / 保存 / 另存为；关闭未保存确认 |
| 多标签 | 多文档；⌘W / ⌘S |
| WYSIWYG | §5.1 格式集合 |
| 大纲 | 随文档更新并跳转 |
| 图片 | 拖拽/粘贴 + 相对路径 |
| 代码高亮 | 围栏代码块语法高亮，与主题协调 |
| 查找替换 | 当前文档 |
| 主题 | 双目录扫描、切换、导入、开关 参考编辑器 目录 |
| 设置 | 默认主题、是否读 参考编辑器 主题、图片策略 |

## 7. 数据流与错误处理

### 7.1 数据流

1. 用户打开文件 → Tauri 读文件 → 前端解析并填入新标签
2. 编辑 → TipTap 更新 → 标签标记 dirty
3. 保存 → 前端序列化 → Tauri 写文件 → 清除 dirty
4. 切换主题 → 前端请求主题文件 URL/内容（经 Tauri）→ 替换 stylesheet

### 7.2 错误处理

- 主题 CSS 加载失败：回退内置默认主题，并提示用户
- 无写权限或路径失效：对话框说明，不静默失败
- 文件被外部修改：提示选择「重新加载」或「保留内存版本」
- 参考编辑器 主题目录不存在：视为无外部主题，不报致命错误

## 8. 验证与验收

- **手工：** 至少用 3 套真实 参考编辑器 主题对照标题、段落、代码块、引用、图片的观感
- **单元：** Markdown ↔ 文档往返（常见 GFM 样例集）
- **烟雾：** 打开 → 编辑 → 保存 → 再打开，内容语义一致
- **主题：** 关闭「读取 参考编辑器 主题」后仅显示自有/内置主题；导入 CSS 后出现在列表中

## 9. GitHub 落地标准

实现与仓库组织遵循常见 GitHub 开源/公开项目实践（最终由用户推送到 GitHub）：

### 9.1 仓库结构（目标形态）

```
Inkmark/
├── README.md                 # 英文为主，含中文简介可选；徽章、截图位、快速开始
├── LICENSE                   # 明确 SPDX（实现时选定，默认建议 MIT，除非另有要求）
├── CONTRIBUTING.md           # 如何开发、提交、PR
├── CODE_OF_CONDUCT.md        # 可选但推荐
├── SECURITY.md               # 安全披露方式
├── .gitignore                # Node、Rust/Tauri、macOS、IDE、构建产物
├── .github/
│   ├── ISSUE_TEMPLATE/       # bug / feature
│   ├── PULL_REQUEST_TEMPLATE.md
│   └── workflows/
│       └── ci.yml            # 安装依赖、lint、test、tauri build（macOS runner）
├── docs/
│   └── superpowers/          # 本规格与后续实现计划
├── src/                      # 前端
├── src-tauri/                # Rust / Tauri
└── package.json
```

### 9.2 协作与质量

- 默认分支名：`main`（创建远程时使用 `main`，本地若仍为 `master` 则在首次推送前重命名）
- Commit message：约定式前缀 + 中文说明（与用户既有规范一致），例如 `feat:新增主题扫描`
- PR：描述动机、测试计划；CI 通过后再合并（用户侧流程）
- 版本：SemVer；Tauri / npm 版本号保持可追踪
- 密钥与签名证书不进库；用 GitHub Actions secrets / 本地环境变量
- README 含：功能简介、系统要求（macOS）、开发启动命令、主题兼容说明、截图占位

### 9.3 发布（第一版可后置，但结构预留）

- GitHub Releases 附带 `.dmg` 或 `.app` 产物说明
- 可选：macOS 代码签名与公证（需要开发者账号时再启用，不阻塞功能开发）
